# 19 风险登记、业务假设与上线门禁

## 原则
状态分类：OPEN（待核实）、CONFIRMED、REJECTED、N/A。没有官方书面/后台应用权限截图及实际测试证据，不能把 OPEN 改成 CONFIRMED。以下均为前期风险，签约需另请专业法律与平台服务商确认。

## 产品可变假设
- A-01：先主做PC Web而非微信小程序/桌面；可评估实际商家反馈。
- A-02：中文/人民币/中国大陆主体为首期默认；后续多语言多币种预留。
- A-03：初期人工确认SKU，AI候选二期。
- A-04：仓库自有打印、商品铺货和复杂ERP集成不阻断V1。
- A-05：SaaS面向其他商家，需要符合服务市场第三方应用资质，不以“自研商家”权限代替ISV资格。

## 风险登记
| 编号 | 风险 | 级别 | 缓解/兜底 |
|---|---|---|---|
| R-01 | 1688自动支付无法批准 | 极高 | MANUAL为稳定默认；禁止浏览器代扣 |
| R-02 | 抖店应用类目定向邀请 | 极高 | 开发前商务确认，否则先Mock内部演示 |
| R-03 | 拼多多普通买家采购接口不开放 | 高 | 适配器关闭，受控手动候选 |
| R-04 | 密文履约跨平台不被允许 | 极高 | 仅选择支持平台指定电子面单的供应商 |
| R-05 | 供应商错货/缺货、价格变化 | 高 | SKU确认、报价时效、付款前校验 |
| R-06 | 并发导致重复采购/双付 | 极高 | 幂等键、唯一索引、UNKNOWN冻结/权威对账 |
| R-07 | 单租户/员工越权 | 极高 | 强隔离、分级授权、回归测试 |
| R-08 | 收费API/限流调整 | 中高 | 访问配额监控、缓存与同步策略优化 |
| R-09 | 供应商迟发造成下游处罚 | 高 | 履约SLA、提前预警、人工换供 |
| R-10 | 成本估算不准确 | 中 | 显示预计/实际分列、逐笔对账 |
| R-11 | 厂商页面后续变化 | 中 | 按业务能力对标，不复制界面或受保护素材 |

## 正式实施必须进一步确认
- 服务商公司主体、注册和资质是否符合平台规定。
- 隐私策略、数据本地化及平台安全环境要求。
- 是否提供沙箱/测试环境及真实上游交易测试方法。
- 自动扣款是否限指定场景/订单类型/签约主体。
- 工单合同约束、发货时效、平台处罚与商家责任划分。
