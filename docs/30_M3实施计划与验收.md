# M3 MANUAL / AUTO / RULE_BASED 支付核心：设计、计划与验收

## 目标与边界

按 prompts/04 和 docs/05、10、11 实施 SP-301～SP-305。沿用 Java21 / Spring Boot3.5.16、Vue3/TS、PostgreSQL、Redis、RabbitMQ 和现有 ProviderAdapter、Outbox、租约/CAS。版本不升级、不增加支付SDK，不包含物流、退款执行、真实账号或真实支付链接。既有 M2 源码和绿色 CI 是基线。

实现由当前会话继续，后端与前端按冻结合同分工，最终整体验证；用户已指定完成整个M3，采用文档基线内的增量方案。首选复用现有数据库 Outbox 和短事务；不增加另一套队列/资金系统，不在请求内执行自动扣款。MFA/双人审批与正式身份留既定生产准入，本地演示不能冒充生产身份。

## 决定与默认值

1. Policy一租户一条，MANUAL、暂停=true；演示可设单笔50000分、每日200000分、每店单笔50000分、每店日200000分、最低利润0。平台硬上限单笔100000分/日1000000分，取更小值；金额都是非负整数分，上限10^12，版本上限JS安全整数。
2. `isPaused`为租户所有店的新付款紧急停止。平台级 `payment_emergency_stop` feature flag / `app.payment-emergency-stop` 为独立总停付门禁，只读查单不受影响；平台管理控制台属于后续运维，本轮不把商家owner提升为平台管理员。
3. AUTO检查有效Mock签约、账户主体、金额、采购权威状态、当前销售权威状态、已确认映射、密文/地区、利润、单笔/日/店额度。RULE_BASED追加可配置的新供应商首次付款人工审核（默认true，以同供应账号历史核验PAID为准）；阻塞返回固定原因，不静默付款。
4. 未签约/已失效/撤销仅在没有在途尝试时进入待人工。紧急停付停止新自动和新人工发起，已在途只读对账。撤销与发起按同租户Policy锁串行，Worker持久化PAYING为发起线性化点；该点之后视为在途，撤销后仅允许查询。
5. PaymentAttempt独立于采购状态；至少一次Outbox事件和唯一业务键确保效果幂等。NEW先落库并预占UTC日预算；调用前提交PAYING和唯一provider key，外部调用在事务外。恢复PAYING/UNKNOWN只能query；没有二次自动支付。明确失败释放预算，其余预占/已付仍计日额度。
6. 自动规划扫描有界，MANUAL不自动建付款任务；AUTO/RULE_BASED满足条件才建唯一attempt/预算/Outbox。显式`POST payments`同样只编排，不直接付款。无签约时不创建假支付流水。
7. 人工入口仅`/payments/mock/{attemptId}`，不含收银台域名或伪造生产URL。创建NEW人工attempt和预算，页面显示Mock权威未付，按钮是合成回执模拟器；回执只作为线索，Worker再次校验账号/采购号/金额/币种/状态才标PAID。UNPAID回执保持待商家付款，不接受客户端金额或支付凭据。
8. Mock故障：NORMAL、DECLINED、PAY_TIMEOUT_BEFORE、PAY_TIMEOUT_AFTER、QUERY_TIMEOUT、AUTHORITY_MISMATCH。持久化合成权威流水，唯一key及purchase约束避免双付；未知只读查询最多5次后MANUAL_RECONCILIATION，仍冻结，不能打开人工重付。
9. 周期对账默认5分钟，及时Outbox重查使用有限退避。只读手动查单可以重新检查同一attempt，不会重置为NEW/PAYING、不重付；每次查单保留脱敏审计/差异记录。租户和店铺范围贯穿API及Worker，所有变更与审计同事务。
10. OWNER有payments.read/manual/manage、paymentPolicy.manage；SUPPORT仅payments.read（分配店范围），策略PUT明确403。所有POST/PUT/PATCH用CSRF，关键命令Idempotency-Key，同key异payload冲突；UNKNOWN状态在幂等缓存前先拦截，不能回放旧入口。

## 冻结API合同（OpenAPI v0.4.0，所有路径前缀/api/v1）

- GET/PUT `/payment-policy`，PUT需Idempotency-Key和version，返回策略/全局暂停/当日占用摘要。
- GET `/payment-mandates?limit&offset`；PATCH `/{id}/mock-state`：status/maxSingleFen/version；ACTIVE有效期由服务端合成，禁止传第三方凭据。
- GET `/payment-queue?limit&offset&storeId&state`：付款财务摘要分页；GET `/purchases/{purchaseId}/payment-status`：同摘要含latest attempt。
- POST `/purchases/{purchaseId}/payments`：编排当前Policy模式，202返回摘要；POST `/purchases/{purchaseId}/checkout-entry`：Mock人工入口，200；两者需Idempotency-Key。
- GET `/payment-attempts/{attemptId}/mock-checkout`：仅本人租户/店可见的Mock人工页；POST `/mock/payment-attempts/{attemptId}/receipt`：outcome=PAID/UNPAID/FAILED，需Idempotency-Key，权威模拟后排只读查验。
- POST `/purchases/{purchaseId}/payment-reconcile`：仅排只读query，202，Idempotency-Key。
- PATCH `/mock/purchases/{purchaseId}/payment-config`：behavior/version，OWNER管理权限，已发起仅允许调整查单故障，不触发支付。
- GET `/payment-reconciliations?limit&offset&storeId`：仅安全差异摘要分页。
