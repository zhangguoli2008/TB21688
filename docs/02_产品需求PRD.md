# 02 产品需求说明书（PRD）

版本 v1.0，所有功能拥有唯一 FR 编号。标记 P0/P1/P2：P0=MVP核心、P1=首个商用版本、P2=后续增强。

## 用户角色
- 商家所有者：授权、套餐、支付策略、财务查看、成员管理。
- 运营：店铺管理、销售订单、商品映射、业务报表。
- 采购员：审核候选货源、上游订单、人工审批。
- 财务：支付状态、对账、成本/利润、账单；不必看到消费者隐私。
- 客服：销售/售后、履约异常处理。
- 平台管理员：套餐、系统运行、技术工单；默认不可跨租户读取敏感订单内容。
- 平台支持：受限临时授权，只能在商家审批后通过审计访问指定问题数据。

## 主要用户旅程
A. 新商家：注册→创建租户→绑定店铺→绑定采购账号（Mock）→设策略→SKU绑定→小额订单试运行→启用自动处理。
B. 已映射订单：销售订单已付→查单→报价→风控→创建采购→付款策略分支→发货→回填→报表。
C. 未映射订单：入待处理→找货候选→用户核实供应商SKU→确认绑定→返回采购流程。
D. 异常：原订单退款、采购金额变化、支付结果未知、供应商超时发货；必须有可见状态、责任人、补偿记录。

## 关键验收标准
- 全链路的每个状态有时间戳、来源、操作人/任务ID和错误码。
- 无商家授权或密文履约资格，界面准确告知而不是显示“已完成采购”。
- 切换付款模式仅影响未进入支付过程的订单；未知支付不能直接切人工。
- 报表金额与数据库采购成本快照/销售实收、退款记录勾稽一致。
- 全量 API 做越权、恶意tenant_id、重复回调等自动化测试。
