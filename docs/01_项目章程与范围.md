# 01 项目章程与范围

## 项目基本信息
- 项目代号：SmartProcure 智采云（工作名，不涉及商标注册）。
- 定位：供淘宝/天猫和抖音电商商家使用的独立多租户自动采购 SaaS。
- 商业模式：按商家订阅、店铺/订单配额、增值服务收费；商家直接向上游供应商付款。
- 产品形式：PC 端 Web（B/S），响应式兼容平板；可选的打印 Agent 延后实施。
- 典型用户：个体店主、多店运营负责人、采购员、财务、客服、SaaS 平台管理员。

## 业务目标
1. 在一个后台集中管理多店销售订单和供应商采购订单。
2. 避免重复、错误采购；首次建立 SKU 绑定关系，后续自动执行。
3. 在**获批通道**上支持有条件的自动付款；否则安全地进入商家确认付款。
4. 供应商发货与下游发货状态一致可追踪，异常可处理。
5. 为每个商家提供可审计的采购成本、预计利润、实收利润及员工操作记录。
6. 单一商家及渠道故障不会扩散到其他租户。

## 目标指标（产品设计目标，不是已达成承诺）
- MVP：完成 1 租户 2 店铺 1 供应商 Mock 的完整订单闭环。
- 生产试点：10–30 商家、每商家 1–20 店铺、每日合计 1,000–10,000 订单的容量评估，实际需压测确定。
- 订单重复创建上游采购单：目标 0（由幂等约束保证）。
- 未核实结果的重复付款：目标 0。
- 越权访问与敏感数据泄露：目标 0；审计覆盖关键操作。
- 指标可观测：接单延迟、匹配率、等待付款时长、采购成功率、发货回填延迟、对账异常率。

## 范围边界
### V1 Mock-first 必做
- SaaS注册/登录、MFA预留、组织成员、角色与店铺范围权限。
- 店铺授权模拟、授权过期/撤销事件及能力开关。
- 订单列表、详情、搜索、同步、异常处理、批量受控操作。
- 商品SKU映射、供应商备选、价格/利润规则。
- 采购单创建、人工确认/自动授权支付**模拟**、重试冻结、对账。
- 履约包裹与物流回填模拟、售后工单与取消协作。
- 经营报表、导出任务（脱敏）、站内提醒、操作审计。
- 配额、订阅状态、计费事件抽象、管理员后台。

### V1.5 在权限条件满足后
- 抖店真实 OAuth、订单事件及订单API；淘宝真实商家授权/订单接口。
- 1688正式采购和物流接口、平台支持的密文履约。
- 商家官方付款入口；获批、有效签约的1688自动代扣。

### V2 可选增量
- AI图搜匹配、供应商评分、商品一键上货、动态换供、AI成本优化。
- 多渠道采购、拼多多**获批**合作通道；供应商履约SLA管理。
- 本地打印Agent、企业ERP/WMS、企业微信/飞书告警。
- 高级财务核算、多组织集团管控、商家开放API。

## 明确不做
- 不代理收取商家采购充值款；不托管资金。
- 不做未经平台许可的普通买家自动化下单/自动付款。
- 不规避验证码、反爬/风控、平台协议及密文数据规则。
- 不复制乐客源码、UI像素布局、图片或商标。
- 不承诺 1688 / 拼多多 API 和自动支付能力必然获批。
