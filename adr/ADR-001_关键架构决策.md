# ADR-001 关键架构决策
状态：接受（2026-10-20 初始方案，实施可通过新ADR调整）

## 决定
1. B/S云端 SaaS 而非所有功能装在客户电脑；本地打印Agent仅可选。
2. Java21/Spring Boot + Vue3 + PostgreSQL + Redis + RabbitMQ + Docker Compose。
3. 模块化单体 + 事务Outbox + 独立Worker，不提前微服务化。
4. 所有渠道 Adapter + Capability + Feature Flag；默认 Mock。
5. 采购和付款分离状态机，PaymentAttempt UNKNOWN 冻结，权威查询。
6. 商家自行在官方上游/支付通道支付，SaaS不托管采购资金。
7. Consumer PII 平台受控，不存普通业务库明文；绝不假设密文可跨平台自由流转。

## 理由
- 低成本高可测试、跨租户易维护、可逐步加入不同平台；最大不确定性在平台准入，不在前端。
- 资金错误不可补救，因此支付严格高于普通后台任务要求。
- 部分外部平台提供订单和物流管理不代表具备普通买家采购/扣款能力。

## 放弃方案
- 纯C/S：商家关机后停止采购，分发和更新困难。
- 每个平台独立一整套系统：代码重复且易产生规则/审计漏洞。
- 默认浏览器RPA完成付款：授权/风控/隐私和可用性风险不可控。
- SaaS统一收商家充值采购款：资金合规复杂、风险高。

## 待复核
在取得平台官方合同和接口权限后，增加 `ADR-002_*` 对指定平台的真实接入范围作单独决策。
