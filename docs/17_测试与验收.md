# 17 测试计划、验收标准与质量门槛

## 测试层级
- 单元：规则、金额分摊、状态机、权限函数、幂等。后端关键模块覆盖率目标≥80%，支付/授权核心≥90%（目标，不替代场景验证）。
- 集成：PostgreSQL唯一约束、Outbox/MQ、Redis并发、Mock Provider多场景。
- 契约：OpenAPI schema、Mock/正式Adapter的能力声明与返回统一性。
- E2E：Playwright演示租户，从订单入库到采购付款和物流回填。
- 安全：跨租户IDOR、注入、CSRF、XSS、callback伪造、重放、导出脱敏、token保护。
- 性能：基于实际目标订单量和API配额模拟峰值；记录P50/P95、失败率、积压、数据库负载，不先承诺吞吐量。

## 必须通过的关键测试场景
| ID | 场景 | 预期 |
|---|---|---|
| T-001 | 相同抖店订单重复推送10次 | 只有1条销售订单、无重复采购 |
| T-002 | 不同租户相同销售订单号 | 相互隔离，均可合法创建 |
| T-003 | 无已确认SKU映射 | 停在待映射，不能执行自动采购 |
| T-004 | 已确认SKU但报价涨价 | 按风险规则阻塞或待人工 |
| T-005 | AUTO无支付签约 | 待人工付款，零自动付款调用 |
| T-006 | AUTO签约有效且条件满足 | Mock支付成功，外部引用保存 |
| T-007 | 付款HTTP超时 | UNKNOWN，0次额外支付请求 |
| T-008 | UNKNOWN后用户点付款 | API返回PAYMENT_STATUS_UNKNOWN，不返回收银台入口 |
| T-009 | 上游创单HTTP超时 | CREATE_UNKNOWN，官方查单而非重复创单 |
| T-010 | 抖店已退款而Worker未采购 | 禁止创建新采购单 |
| T-011 | 上游已付但下游取消 | 进入售后协调，而非立刻本地标退款成功 |
| T-012 | 1个采购单2包裹 | 两次正确独立同步/回执 |
| T-013 | 外部发货回填失败 | 保持独立失败状态并可重试 |
| T-014 | 客服访问payment-policy PUT | 403，审计不泄漏凭据 |
| T-015 | 租户A读取租户B采购ID | 404或403且不能得知内容 |
| T-016 | 回调验签失败/事件重放 | 拒绝/安全去重，不更新状态 |
| T-017 | 全局停付开关触发 | 不再发新付款，仍能查询已发起款状态 |
| T-018 | 拼多多接口无批复 | UI标不可用，所有买家自动创单/支付请求失败关闭 |
| T-019 | 报表退货退款 | 预计利润与实际利润分别正确；差异可解释 |
| T-020 | 订单隐私字段出现在日志/导出 | 测试失败/CI阻断 |
| T-021 | 租户切换+并发请求 | 不串租户，权限每次正确 |
| T-022 | 手工付款点击完成但上游未付款 | 保持WAIT_MERCHANT_PAYMENT |
| T-023 | 付款授权刚撤销 | 新自动付款失败关闭；在途订单仅对账 |
| T-024 | Worker重复事件至少一次投递 | 采购与支付仍严格幂等 |
| T-025 | 金额极值、负价/空运费/折扣尾差 | 输入拒绝或正确分摊，不用浮点 |

## 验收环境与数据
- 演示数据全合成，不含真实用户PII。
- Mock Provider支持模拟：成功、明确失败、超时未知、乱序事件、降价/涨价、缺货、部分发货、退款中。
- 测试前初始化1管理员、2商家租户、每租户2店铺、2供应商、6 SKU；两个租户使用同样外部订单ID验证隔离。

## 发布门槛
- CI绿色；安全扫描无高危/严重项未处理；Flyway迁移在空库及升级库均通过。
- 关键付款、跨租户与密文数据检查测试全部通过。
- 发布文档记录未开放的平台能力；真实通道仅在完成相关GATE审查后开启。
- 试点前完成备份恢复演练、禁用紧急停付验证、客服异常处理培训。
