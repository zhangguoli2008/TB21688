# Codex M6：真实平台接入（只有平台Gate通过后才使用）

**前置证据**：要求用户提供所属主体的正式API审批、应用凭据获取方式（不得在聊天中粘贴秘钥）、官方最新接口文档版本、签约资格、密文环境要求和已批准的沙箱账号。不具备时停止真实API开发，继续交付Mock和接口清单。

1. 对每个Provider独立建立`docs/platform-evidence/...`，列出被批准的每项API、scope、调用限额、错误码、沙箱样例及签名规范。
2. 保持`SupplierAdapter`的能力开关真实准确；未获批方法必须CAPABILITY_UNAVAILABLE，不做浏览器RPA绕过。
3. 先只读授权和订单查询，再测试创单，最后是物流回填；支付授权/收银台/免密代扣最后接入且需双重审批。
4. 订单个人信息仅按获批的密文与受控环境处理，跨平台不任意转交明文地址。
5. 每条真实接口提供模拟测试、官方沙箱/测试商家验证、回滚开关与对账日志。
6. 先小规模 `MANUAL` 生产试点，再逐租户开启通过合法签约的 `AUTO`。

拼多多必须先验证是否有第三方普通买家采购+付款的正式合作接口。若没有，此功能保持不可用，不通过浏览器模拟购买替代。
