# 05 订单、采购、支付、履约状态机与补偿

## 一条完整业务主线
1. 接收销售订单推送（仅记录事件ID和安全业务字段）→验签/限重放→事件入库。
2. 解析并去重，异步按店铺订单ID重拉权威详情，记录销售子项、实付金额、应履约量、截止时刻。
3. 未付款或已取消的订单不得采购；已付款/待发货进入SKU映射。
4. 使用已确认SKU映射并校验平台密文履约支持；缺映射走待人工核对候选流程。
5. 引用新鲜报价，核验商品价、运费、数量、地址支持、利润和店铺限额，创建 `PurchaseIntent`。
6. 在事务内确保本订单子项数量不会超采购；写采购意图、Outbox；Worker执行采购创建。
7. 获取上游采购ID；**绝不以HTTP成功=付款成功**；自动与人工支付都通过支付编排器。
8. 支付完成并权威核验后等待供货商发货；采集包裹，按下游能力回填。
9. 售后/物流异常独立追踪，报表投影从领域事实事件计算。

## SalesOrder 状态
`NEW -> VERIFIED_PAID -> SOURCING -> READY_TO_PURCHASE -> PROCUREMENT_IN_PROGRESS -> AWAITING_SHIPMENT -> PARTIALLY_SHIPPED -> SHIPPED -> COMPLETED`
异常/并发分支：`CANCELLED / REFUND_IN_PROGRESS / MANUAL_REVIEW / SUSPENDED`。不得把售后终态直接覆盖历史销售状态；销售原始状态和本地履约状态分别存。

## PurchaseIntent 状态
`NEW -> VALIDATING -> APPROVED -> CREATING -> CREATED -> AWAITING_PAYMENT -> PAID -> FULFILLING -> COMPLETED`。
可进入 `REVIEW_REQUIRED`, `FAILED`, `CANCEL_REQUESTED`, `CANCELLED`；CREATING请求超时进入`CREATE_UNKNOWN`，核实后才允许重试。

## PaymentAttempt 状态
`NEW -> PAYING -> PAID`，明确拒付 `PAYING -> FAILED`；结果不清 `PAYING -> UNKNOWN -> [PAID | FAILED | MANUAL_RECONCILIATION]`。
- **不允许** `UNKNOWN -> PAYING` 直接再次执行。
- 商家点击“去付款”不能使付款成为 PAID；依赖外部支付/采购权威状态。
- 自动付款签约不可用、金额超限时转 `WAIT_MERCHANT_PAYMENT`，但前提是当前没有可能成功的在途支付尝试。
- 如果外部平台支持幂等请求标识，可沿用相同支付 attempt 标识；不支持时必须查询官方状态、人工介入，禁止自动第二次付款。

## Shipment 状态
`NOT_CREATED -> LABEL_CREATED -> HANDED_OVER -> IN_TRANSIT -> DELIVERED`；下游回填另有 `NOT_SENT -> SENDING -> ACKED | RETRY_WAIT | BLOCKED`。物流更正保存版本，记录平台权威回执。

## Aftersale 状态
`REQUESTED -> UNDER_REVIEW -> SUPPLIER_COORDINATION -> RETURN_IN_TRANSIT -> REFUND_PENDING -> RESOLVED`；支持 `REJECTED`, `PLATFORM_ARBITRATION`。退款金额从独立 refund transaction 记录，不修改历史 paid 金额。

## 幂等与补偿设计
| 任务 | 幂等键 | 超时恢复 |
|---|---|---|
| 接单消息 | provider+app+eventId | 查订单权威状态/消息入库去重 |
| 上游采购创建 | tenant+purchaseIntentId+version | 用外部关联标识查询已有上游订单；未知冻结 |
| 自动付款 | tenant+purchaseId+paymentAttemptId | UNKNOWN + 查外部权威状态，禁止重新付 |
| 下游物流回填 | tenant+salesOrderId+shipmentId+version | 查询回填状态，按平台规则重放同一包裹信息 |
| 售后创建 | tenant+salesOrderId+aftersaleExternalId | 查外部工单状态 |

Worker故障时：基于Outbox至少一次投递 + 业务唯一键实现效果幂等，严禁声称队列提供 exactly-once。对账作业定期发现 `UNKNOWN`/`PAYING`/`CREATING` 超时项，在有限时间内重查后转人工。

## 事务边界
- 本地数据库变更、Outbox事件写入同一数据库事务。
- 外部HTTP调用在事务外执行，不能长时间锁表。
- 回调只是状态变化线索；必须验签/匹配金额、商户、订单，并按需回查权威状态。
- 每个状态迁移使用乐观版本 `version` / CAS 条件，并记录事件。

## 接口出错分类
`RETRYABLE`（429、临时5xx）指数退避含抖动；`PERMANENT`（无权限、无效SKU）转人工；`UNKNOWN_SIDE_EFFECT`（创单/付款后超时）冻结并查单；`BUSINESS_BLOCKED`（订单已退款等）停止执行。
