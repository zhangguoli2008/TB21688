# M1 店铺授权模拟与销售订单

范围：SP-101～SP-104；基于已验收 M0 增量实施。所有业务数据与平台交互为 MOCK，不代表真实订单、授权或付款。Java/Spring Boot、Vue/TS 及依赖版本沿用 M0 锁定版本，不增加第三方 SDK。

## 实施核对与默认值

1. 渠道为 DOUYIN/TAOBAO，运行模式另存/返回 MOCK，不能把 Mock 声称为平台授权。
2. 店铺 `enabled` 与授权 `ACTIVE/EXPIRED/REVOKED` 分离；到期时读取即视为 EXPIRED。ACTIVE 模拟有效期为30天。
3. CRUD 采用注册、查看、改名、禁用/启用；保留历史订单，不物理删除。改动以 version CAS 防并发覆盖。
4. 管理请求租户来自会话；Webhook 租户来自服务端 integration→store→tenant 映射，客户端不能指定。
5. OWNER 可读本租户全店；SUPPORT 按 member_store_access 限定店铺；不可见对象统一404。每个租户两个合成店铺。
6. 店铺禁用、授权撤销/到期、租户停用均阻止接收及 Worker 新同步，已有业务记录可按权限只读。
7. Inbox 使用 provider+integration+eventId 去重；同事件不同内容或 nonce 复用拒绝。销售单仍使用 tenant+store+externalOrderId 唯一键。
8. Mock HMAC-SHA256 覆盖 timestamp、nonce、integrationId、原始body；过去300秒/未来30秒之外拒绝，常量时间比较。伪密钥仅用于演示，不构成真实平台验签。
9. 回调仅传订单引用/源版本/时间；状态、金额、子项从独立 Mock 权威快照经 ProviderAdapter 重查，不信任推送状态。
10. Inbox 与 Outbox 同事务；数据库持久 Worker 采用 lease、SKIP LOCKED、有限重试和 DEAD/BLOCKED，至少一次执行；本轮不声称 RabbitMQ exactly-once。
11. 权威 sourceVersion 单调；较旧事件重查最新详情，不能回滚订单；业务唯一键、事务和版本约束承受重复消费。
12. sourceStatus 与 localStatus 分离。本轮仅 UNPAID/PAID/CANCELLED/REFUNDING/REFUNDED 与 NEW/VERIFIED_PAID/CANCELLED/SUSPENDED，不推进采购和履约。
13. 金额 long/bigint 分，子项金额合计校验、数量约束；只保存合成商品和安全引用，不保存地址或支付凭据。
14. 列表 limit 默认20/最大100，offset最大10000；q 为精确外单号；时间按 sourceUpdatedAt 的 UTC [from,to) 筛选，UI Asia/Shanghai；筛选与 URL 同步。
15. T-010/014/015 与 T-021 的正式租户切换涉及后续能力。记录本轮边界断言和后续待验收项，不为编号增加采购/支付系统。

## 文件、模块与依赖

1. 合同先行：`contracts/openapi.yaml` v0.2.0 定义 /stores、/stores/{id}、/orders、/orders/{id}、Mock scenarios 和签名 Webhook；保留其余未实现设计合同。
2. V2 增量迁移：店铺启用/integration、销售源版本、Mock权威快照、时间轴、请求幂等键、Inbox安全元数据及Outbox调度字段/索引/复合外键；不改V1。
3. API：store 数据范围与 CRUD → 销售查询/ProviderAdapter权威读取 → 签名Inbox/Outbox → Worker/模拟场景；auth 扩权限，独立demo/test种子；业务变更安全审计。
4. Web：客户端校验 → 路由/权限导航 → 店铺中心/注册 → 订单筛选/详情/模拟事件；复用 M0 视觉，不显示未来采购/支付的假数据。

## 审查与边界

独立审查确认两类并发一致性风险，修复验收要求包含真实PostgreSQL和受控线程屏障：详情的订单/子项/时间轴使用一致性读快照；Worker apply持有Outbox行锁验证租约，DONE条件更新失败必须回滚业务，防止过期租约回收后任务终态与业务结果分离。

- 时间轴只返回最近100条安全事件；订单页店铺选择器显示前100个可见店铺，有明确提示；店铺列表本身仍可分页。
- 同权威版本但内容冲突时保留原订单，有限重试后DEAD，记录固定错误码及审计；不悄然覆盖历史或创建后续人工采购队列。
- DEAD/BLOCKED可从数据库和安全审计追踪；管理重放UI和保留策略自动清理留M5。Webhook原始body、签名、密钥不入库，只保留安全引用与摘要；生产保留期限需按授权和合规另行确认，不能直接使用演示环境。
- M0生产身份/多实例会话、正式平台OAuth及全部真实交易能力仍未实现。M1不开放采购执行器、支付策略业务、付款或物流。
- ElementPlus主包约1.04MB，构建有>500kB提示；未隐藏告警或为本轮变更依赖版本。

### 可复现命令

使用Java21、Node24、专用PostgreSQL测试库；M0_TEST_DB_URL/USER/PASSWORD按README设置，不能使用生产库。本机专用库位于127.0.0.1:55432，其他环境可用Compose默认端口5432。

```bash
./mvnw --batch-mode -Pintegration verify
(cd apps/web && npm ci && npm run lint && npm run typecheck && npm test && npm run build && npm audit --audit-level=high)
.local/venv/bin/openapi-spec-validator contracts/openapi.yaml
python3 scripts/check-safety.py
docker compose up --build --wait --wait-timeout 300
M0_REQUIRE_HEALTHY=1 .local/venv/bin/python scripts/smoke-m0.py
.local/venv/bin/python scripts/smoke-m1.py
docker compose restart api
docker compose up --wait --wait-timeout 120
M0_REQUIRE_HEALTHY=1 M0_BASE_URL=http://localhost:4173/api/v1 .local/venv/bin/python scripts/smoke-m0.py
M1_BASE_URL=http://localhost:4173/api/v1 .local/venv/bin/python scripts/smoke-m1.py
```

本机为避开其他项目服务，实际容器API/Web宿主端口为18080/14173，基础设施为55433/56380/55672；变量见`.env.example`，不会停掉其他项目服务。测试创建合成记录用于检查，可重复执行，不物理清空用户数据。
